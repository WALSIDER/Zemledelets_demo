# ЗемледелецЪ — сайт для Cloudflare Pages

Сохранены текущие страницы, каталоги, карточки, регистрация, вход, серверный профиль,
сбор подписок и новости. В облаке данные хранятся в Cloudflare D1; локально — в JSON.
Редактор карточки компании в новом кабинете, как и в исходном проекте, сохраняет
изменения в браузере. Функции оплаты и публикации объявлений, которых не было в
исходном сервере, эта адаптация не добавляет.

## Развернуть из GitHub

1. В Cloudflare откройте **Workers & Pages → Create application → Pages → Import an existing Git repository**.
   Выберите `WALSIDER/Zemledelets_demo`, ветку `main`.
2. Укажите настройки сборки:

   | Поле | Значение |
   |---|---|
   | Framework preset | `None` |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | оставьте пустым |

3. В настройках проекта **Functions / Runtime / Compatibility flags** добавьте
   `nodejs_compat` и установите compatibility date `2026-09-01`.
   При необходимости задайте переменную сборки `NODE_VERSION=22.19.0`.
4. В разделе **Storage & databases → D1** создайте базу `zemledelets-demo`.
5. Откройте проект Pages → **Settings → Bindings → Add → D1 database**.
   Имя привязки (variable name) должно быть **`DB`**. Выберите созданную базу.
   Привяжите базу к Production. Для Preview используйте отдельную тестовую базу.
6. Повторите deployment (**Retry deployment / Create deployment**), чтобы применить
   настройки. Таблицы создадутся автоматически при первом обращении к API.

Без привязки `DB` каталоги доступны, но регистрация, вход с сохранёнными облачными
аккаунтами и подписка требуют базы. При попытке записи сервер выдаёт понятную ошибку,
а не сообщает о ложном сохранении.

Cloudflare Pages, Functions и D1 имеют бесплатные лимиты. Бесплатность работы
зависит от объёма запросов, CPU и использования базы, а не от наличия этого README.

## Новости и Ollama

- В репозиторий включены существующие материалы новостной ленты.
- Обновление из внешних источников запускается при обращении к новостям, с интервалом
  30 минут и небольшим числом новых материалов за один запуск. Постоянный процесс
  `setInterval` на Pages не используется. Внешние источники должны быть доступны.
- Переменная `NEWS_AUTO_SYNC=false` отключает автоматический импорт в Cloudflare.
- Для ручного вызова `/api/news/sync` настройте секрет `NEWS_SYNC_TOKEN`; передавайте
  его в заголовке `x-sync-token` только из доверенного инструмента, не из браузерного JS.
- Cloudflare не может обратиться к Ollama на вашем `127.0.0.1`. Для перевода и ИИ
  требуется отдельно доступный сервис и переменная `OLLAMA_API_BASE`. Без него
  доступны существующие материалы и импорт русскоязычных материалов без ИИ.
- Длительные внешние запросы могут достигать лимитов Pages Functions. Для фонового
  импорта независимо от посещений потребуется отдельный планировщик/Worker.

## Локальный запуск

На исходном компьютере откройте `Запустить сайт.cmd`. Нужен Node.js; скрипт также
ищет имеющуюся установку в соседнем проекте StrelaPortal. На другом компьютере
установите Node.js LTS или запустите `npm start` (по умолчанию порт 3000).

Проверка Cloudflare локально:

```powershell
npm ci
npm run build
npm run preview:cloudflare
```

Wrangler создаёт локальную D1 в `.wrangler/`. Для проверки API на тестовой базе:

```powershell
python scripts/check_cloudflare.py http://localhost:8788
```

## Данные и обновления

Локальные пользователи, пароли, сессии, подписчики, `.env`, логи и резервные копии
не публикуются. На размещённом сайте аккаунты нужно зарегистрировать заново.
Новые данные сохраняются в D1 и переживают повторное развёртывание приложения.
Записи изменяются атомарно; конфликт параллельных изменений возвращает HTTP 409,
который предлагает повторить действие.

Исходный `server.js` служит общей реализацией API. Сборка преобразует его в ES-модуль
и подключает адаптер запросов Cloudflare; отдельной расходящейся копии API нет.
Страницы копируются в корень `dist`, а маршруты с `.html` и без расширения
поддерживаются клиентским приложением.
